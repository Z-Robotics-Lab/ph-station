# Agent Note: RSI 评估证据与安装状态

Status: implemented

English | [中文](2026-09-05-rsi-evaluation-evidence.md)

## Problem

机器人改进试验可能通过更多计划节点，却没有满足更多任务条件。开发阶段的改进也不能证明已经获得安装技能所需的独立证据。控制台若把两种结果都称为发布，就会掩盖它们的差别。

## Decision

RSI 页面使用共享主题变量作用域。宽面板中媒体和分析等宽排列，容器宽度不超过 860px 时堆叠；实时图像按视口限制高度，最高 440px，并完整容纳画面，避免原始尺寸图像把分析内容推到首屏下方。

RSI 轮次展示后端对固定任务条件的评估，并将开发评测接受与验证安装分开。缺失值保持未知。紧凑序列直接提供目标进度；客户端不选择目标，也不计算历轮最佳值。历史节点通过率仍可作为诊断数据查看。试验图的绿环由显式接受结果决定，历史发布记录保留历史标记。

诊断与经验以可展开的后端记录展示。跨任务迁移展示记录中的首次接受轮次与预算，包括预算内尚未观察到接受的情况、经验检索截点、实验条件和后端结论范围。额外开发种子复测是实时阶段，不构成留出集安装证据。原有实时进度、父轮次图、逐种子证据、媒体与日志保留原来的 board 路由和职责归属。

迁移资源测量还区分开发周期的累计成本、首次接受改进成本，以及所选轮次之前最近一次接受之后的成本。最后这一段包含当前轮次，即使该轮被接受。每项测量保留后端记录的六种资源单位；UI 不进行累加或金额换算。首次接受记录为 null 表示尚未接受，而已有记录中的 null 字段表示成本未测量。保留这一区别可以避免把缺失证据显示成零成本改进。最近周期默认折叠，让成本展示保留在已有迁移视图中。

较宽的证据在局部横向滚动：轮次图、任务热图与种子矩阵在面板宽度的容器内保留完整内容。网格中的文字列可以收缩并折行显示标识符，实时区域按可用面板宽度重新排列。如果把图的滚动容器设为完整历史宽度，较远轮次获得焦点时就会移动整个面板，遮住无关的媒体与审计内容。浏览器验收覆盖在窄面板中选择较晚轮次，同时外围证据保持横向位置不变。

skill-author 预设通过现有收件箱提交完整计划提案。提案保留原节点顺序、calls、goal/tasks 与 verify，可插入已安装的 action skills 并附合法验证。完整组合后的 persona 快照固定这一范围，以及开发评测接受与安装的区别。

新建与继续运行的简报显式请求 LLM 提案。没有规则提议器选项和自动回退；规则仅作为历史来源展示。显式收件箱提案仍是独立的提交通道。模型审计状态区分已提出候选、主动放弃、校验预算耗尽及模型调用失败。控制台展示后端模型、提示摘要、理由和结构化错误，可展开的 JSON 保留已封存审计摘要与哈希。该摘要不暴露完整请求消息或模型原始答复。失败的 campaign 明确标为失败并展开运行日志。复测评估为 null 时显示未复测，不伪造分数或曲线点。聚焦测试覆盖这些状态以及仅用 LLM 的启动与继续运行；完整组合后的 skill-author 快照固定相同报告规则。

启动控件默认提交持续运行简报，不限制完成的周期数，但每周期资源仍有上限。有限模式保留正整数周期上限与简报共享预算。模型停止原因属于单周期，campaign 单独记录整体停止原因；周期间等待仍属于运行中并可取消。实时周期预算可以重置，简报累计成本持续增加。客户端直接展示两个作用域，阻止对尚未结束的简报重复启动，并区分缺失测量与显式无总上限。

模型设置页签只编辑下一次“开始 / 继续”的简报。草稿字段留空时由 harness 决定默认值，因此异步发现不会覆盖操作员的选择。board 负责模型发现和可用推理强度名称；发现不可用时，原生 datalist 仍允许输入明确的模型 ID。当前战役已记录配置，以及每轮请求模型、推理强度和实际模型标识，作为独立证据展示。更改设置不会修改或重启已有简报。

## Alternatives considered

**把发布视为验证。** 不采用，因为开发种子的改进不会执行安装评测流程。

**继续优化节点通过率曲线。** 不采用，因为候选可修改的图能改变分母。节点结果仍是有用的诊断证据，但不定义任务目标。

**在浏览器计算进度与迁移。** 不采用，因为 Python 负责证据聚合，控制台必须展示与 agent（智能体）获得的相同判定。

## Consequences

提交和取消在更新本地待处理状态前区分 RPC 失败与成功响应。取消失败时保留同一简报供重试，并显示后端错误。

历史记录由当前 RSI 组件展示，不依赖旧 campaign 表格中未使用的文案或样式。技能库记录由 `ui-ph-vault` 拥有，因此本包不保留重复的行类型。

旧 campaign 的历史证据仍可阅读，也不会因此获得验证声明。固定目标曲线要求后端提供 evaluation；新协议序列中的缺失 evaluation 不会回退到节点通过率。聚焦的渲染测试覆盖接受但未安装、缺失数据、媒体与日志保留，以及节点通过率虚高不能推动目标曲线。本地浏览器检查完整控制台及其轮次选择流程。

首个有测量值的轮次以点显示，因为 SVG 不会绘制只有一个点的折线。缺失测量仍不产生点。该行为已针对 588 个历史轮次之后的一轮真实 RoboCasa 实验核验。

训练图默认保留全部历史，在目标或协议版本边界断线，并用虚线标出切换。可单独选择一个版本；只有一轮时说明为何仅显示一个点。新评测版本不会使默认总览中的旧轮次消失，跨版本的数值变化不代表学习进展。横轴采用实际轮次，单点观测也可见；缺失测量与轮次间隔会断线。策略线仅在明确接受时采用复测值，独立的候选菱形保留未通过的试验而不将其提升为策略。配对竖线将每次复测与自身基线对比。每页 20 行的历史表替代父子树，与曲线共享详情选择，并支持键盘导航和实时跟随。查看旧页会固定轮次，轮询不会替换其证据。SVG 按容器宽度计算坐标，使窄屏轴文字保持可读。纯数据和渲染测试覆盖周期边界、缺失数据、接受字段优先级、选择、分页和新增轮次；localhost mock API 验证桌面与手机渲染，不启动实验。

诊断旁可展开逐种子原始验证观测，保留两阶段的评估、被阻断的验证器读取和终局观测。null 仍表示未知，false 仍保持 false。操作员可据此检查被拒绝的 actor 依赖测量，节点执行矩阵保持不变。

真实 LLM 运行验收发现，切换 campaign 时会短暂显示旧任务证据。现在会话与任务共同限定 campaign 数据，轮次进一步限定完整证据和媒体，请求归属检查拒绝已离开选择的响应。加载时不显示其他任务的图或审计。延迟响应测试覆盖不同任务的同号轮次、迟到的完整证据与媒体，以及切走再切回后旧 campaign 请求才返回的情况。

选中运行中的轮次后，现有序列轮询首次出现该轮封存行时重新读取完整证据和媒体；先前的空读取不会遮住最终审计、采样反馈或片段，不另加轮询。

模型预算可选地提供每次新实测采样之间的批量只读调用上限。控制台展示记录的上限与重置条件，不根据累计取证次数推算剩余额度。缓存结果与错误不会重置它；旧记录缺少上限时保持缺失。组件测试保留显式零值，并省略缺失或 null 的上限。

聚焦组件测试覆盖省略默认字段、提交的模型与推理强度 JSON、手动 ID、模型发现与传输失败、迟到的发现响应、刷新、页签草稿保留，以及与已记录配置的区分。主机桥接测试固定只读 storecli 命令与原样返回的发现结果。这些测试不调用模型或运行实验。
