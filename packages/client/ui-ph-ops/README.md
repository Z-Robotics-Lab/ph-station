# @deepseek-ai/dsh-client-ui-ph-ops

English | [中文](README.zh.md)

physical-harness operator rail + mission cockpit + the RSI page. Browser surfaces that read the harness evidence layer through the board Remote and render only:

- **Mission cockpit** — a `conversation.view` tab (任务图). The graph-first view of the running mission: goal → task node → stage pipeline plus the capability-wiring fan, one interactive React Flow DAG (pan/zoom, minimap, click-to-select). A run-history strip switches between sealed task attempts; clicking a node opens its evidence (stages, faults, provider `ref`) beside the graph. Status color is the established three (green pass / red fail / neutral pending), so it reads as one system with 战报/演进/账本.
- **Skill library** — lives in [`ui-ph-vault`](../ui-ph-vault/README.md) (view id `vault`, 技能库), which owns skill records and their presentation. This package registers no skills tab.
- **RSI page** — the `conversation.view` tab `rsi` starts or continues an evolve brief, cancels its open brief, and selects persisted campaigns and rounds. It preserves the live phase stepper, seed and node progress, runtime frames, training curve and paginated round history, per-seed baseline/trial matrices, kept video clips, dropped-media keyframes, usage, and operational logs. Board failures appear explicitly, including submit/cancel RPC errors. Failed cancellation retains the pending brief for retry. Reads poll every 2s while running and every 10s otherwise; full evidence is fetched only for the selected round. `evaluation` displays the fixed task objective, before/after success counts and progress, development acceptance with its reason, and an independent verified-installation status. `not_evaluated` never becomes installed because a trial improved. The series uses backend fixed-obligation progress; historical node rates are labeled diagnostic. The history table records explicit development acceptance; legacy publication and confirmation records are labeled historical. Expandable `diagnosis` and `experience` records preserve backend evidence verbatim. `transfer` displays prior tasks, first accepted round, total trials, censored observations, the recorded condition and experience cutoff, and the backend’s claim limits verbatim. The optional `confirm` phase is labeled additional development seeds; its seed board shows only reported extra seeds, and it never implies held-out installation evidence. The legacy strict-evaluation views remain collapsed below campaigns when legacy stores exist. The dashboard uses equal-width media and analysis columns above 860px of panel width and stacks them below that width. Live frames are capped at 440px high, clip tiles at 260px; both preserve the whole image with `object-fit: contain`. Charts fill their analysis column, and logs remain full width.
- **Operator rail** — a `sidebar.section` occupant: a persistent stack of at-a-glance cards (mission mini-map, progress, runtime vitals, RSI ticker — the evolution session's newest campaign off `rsiCampaigns` (running first; survives a restart), its `task · 第 r 轮 · best k/n · status`, with the legacy promotion tally beneath only when a legacy store exists) answering "where is the mission / is it progressing / is the machine healthy / is it getting better" without a click. Collapses to status dots when the sidebar is an icon rail.

Every number comes from `board.store` — the Python `session_progress` fold and the session chain — through the board Host Remote (`sessionProgress`, `session`, `sessions`, `runtimeStatus`, `runtimeEvents`, `hostVitals`, `modelServer`, `policyServer`, `restartServices`, `health`, `stores`, `cards`, `rsiCampaigns`, `rsiRun`, `rsiSeries`, `rsiFrames`, `runtimeFrame`). No statistics are computed here (the charter's audited hard rule: the fork renders, Python aggregates). The vitals card also carries the host's own headroom from `hostVitals` — per-GPU VRAM with the process holding it, RAM, and free disk — on its own 5s poll, because those move without a board write to follow and a full card kills the resident runtime; above 90% the meter turns red. The thresholds pick a colour, never a number. Beneath the VRAM meter that explains it, the card carries the only control on this surface: `modelServer` starts and stops the box's local model server, badged stopped / loading / running (`running` without `healthy` is the 1-2 minute load) with the button held down until a poll confirms the switch. It switches the service process only — which model a request routes to stays the model selector's choice — and the rail passes a literal action word; the whitelist, the launcher path, and the kill guard are all `board.store`'s. Beside it, `policyServer` is the same switch for the pi0.5 policy server (badged not started / running (not serving) / serving, with the short checkpoint sha) as explicit Start / Stop buttons, noted as not started by default, ~18 GB VRAM, and unable to coexist with the local model. Last, `restartServices` restarts the harness services behind an in-widget two-step confirm (the first click arms the button, a second click within 8s fires; never `window.confirm`) with a rebuild-console-first checkbox; after firing, the card shows a restarting line and polls `health` (after a short grace, since the helper answers before the console goes down) until the console answers again, then shows the `restart` row's state and last line. The rail reads `runtimeEvents` only to tell a still-open run from a settled one — the board's own `task_claimed` / `task_done` / `task_failed` markers, read verbatim, never a verdict computed here.

The RSI training curve defaults to fixed task progress, with a whole-task success-rate selector. It defaults to all historical rounds, split into separate lines at objective/protocol boundaries with dashed version markers. Individual epochs remain selectable and unidentified evaluations are isolated; a single measured round has an explicit one-point explanation. The current policy uses the candidate result only after explicit backend acceptance, otherwise that round’s baseline. Candidate diamonds remain separate, with a thin line to their paired baseline. Missing observations and skipped rounds break the raw policy line; no smoothing or filled values are introduced. The latest 20 rounds appear in a scrollable table with results, policy/candidate values and cost. Chart and table selection share the detail reader; arrow keys and Home/End navigate rounds. Paging into history fixes a selected round and exits live follow; Follow latest returns to the full history and incoming results. The chart measures its container so axis text remains legible on narrow screens. Expandable raw observations preserve per-seed evaluations, verifier dependencies (including blocked reads), and terminal observations.

New and resumed RSI briefs default to `proposer: "llm", continuous: true, rounds: 0`; there is no rules selector or automatic fallback. Continuous mode renews bounded learning cycles until operator cancellation or an external error. Finite mode submits `continuous: false` with a positive completed-cycle limit and retains the brief’s shared budget. A second start for a task with an open brief is disabled; Stop remains available during backoff. Historical rules rows remain labeled historical, and explicit inbox proposals retain their recorded source. The LLM audit distinguishes `proposed`, `abstained`, `rejected`, and `error`, displaying model identity, prompt digest, reason, and structured error stage/type/message. Its expandable JSON preserves the sealed audit summary and hashes exposed by the board; it does not contain complete request messages or raw model responses. Abstention and validation-budget exhaustion describe the completed cycle; they do not imply that a continuous run has stopped. The status area shows the current learning cycle, the wait until its next cycle, and the overall stop reason separately from the selected round’s cycle outcome and model stop reason. Model-call errors end as failed, with the log open. A null `evaluation.after` is labeled not retested and contributes no after-progress point.

Campaign reads belong to the selected session and task; full evidence and media also belong to the selected round. Switching tasks shows loading until that task's campaign arrives, and late responses from an earlier selection are ignored, including after revisiting the same task. Equal round numbers in different tasks never share evidence. If the selected round is still running, its full evidence and media are fetched again when the existing series poll first reports its sealed row.

Online program-policy rounds reuse the model audit for model calls, evidence reads, exploratory trial calls, byte budgets, output-token usage, and the recorded stop reason. Request bytes are cumulative; request and tool-result limits apply individually, and the output-token limit applies per model call. The separate `run_budget` records cumulative consumption within the submitted brief, not the full campaign history; it does not reset between cycles. `cycle_budget` shows the current cycle’s limits and consumption. Continuous briefs carry explicit null total caps, displayed as no total cap, while absent measurements remain unknown. The current status and the selected round’s audit retain their own budget records. Missing measurements remain unknown, including incomplete API token usage. These counters describe the model loop, not the console's polling. Program policy identities show the baseline, candidate, active and parent versions with the backend update decision; this is program-policy improvement without weight training. Expandable learning records retain exploratory probes and feedback, which do not establish paired development acceptance or verified installation. The fixed-objective result and its chart remain the authoritative paired measurements.

Transfer resource costs cover one development epoch. The compact transfer view shows recorded accepted updates, total resources and the first accepted update's cost: episode attempts, model calls, input bytes, LLM tokens, simulator seconds and elapsed seconds. No first acceptance is labeled “Not yet accepted”; an accepted update with unmeasured costs shows `—` per field, while measured zero remains zero. Tokens are resource counts, not a monetary estimate. Expandable cycle costs run from the acceptance preceding the selected round through that round, including a newly accepted round. The browser neither sums these records nor derives an acceptance decision from them; historical rows without costs retain their existing view.

The round graph, task heatmap, and seed matrices scroll horizontally within their own containers. Long histories and identifiers do not widen the RSI panel or move media outside it; live panes stack when the panel is narrow.

When recorded, `llm.budget.limits.max_read_calls` displays the limit on batched read-only calls between newly measured probes. Cached results and errors do not reset this allowance. Missing historical limits are omitted; the console does not infer an allowance from total evidence-read counts.

The internal Run / Model settings tabs keep the next-run draft separate from the campaign’s recorded `llm_config`. Model ids and effort choices come from `rsiModelOptions`; the model input also accepts an explicit id when discovery fails. Empty selections omit `llm_model` / `llm_effort` and use the displayed backend defaults (`off` disables thinking). Explicit selections travel only with the next Start / resume brief. Tab changes and discovery refreshes preserve the draft, and never restart a running brief. Historical campaigns without a recorded configuration remain unknown. The selected round shows its requested model and effort beside the actual model identity.

## Dependencies

Two net-new runtime deps, both MIT, justified against the redesign spec (`physical-harness/docs/ph-ui-redesign.md` §5):

- **`@xyflow/react`** (React Flow v12) — the interactive mission DAG: custom status-colored nodes, pan/zoom, minimap, controlled selection for click-to-drill. Hand-rolling this in SVG is the larger diff and worse interaction/a11y. React Flow renders its own DOM subtree, so it does not inherit the panel language; `ops.module.css` overrides its `--xy-*` variables against `currentColor` (which flips with the app theme) and sets `colorMode="system"`.
- **`@dagrejs/dagre`** — layered DAG layout feeding React Flow (which does not auto-position). Small and sufficient for our single-digit-to-dozens node counts.

## Model Experience

None, as both surfaces render board Remote state for the browser operator and the chat LLM reads the same `board.store` functions through the MCP server.

#### KV Cache effect

None; the package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- **Clips stream without Range support.** 关键片段 renders each `rsiFrames` path as a card off the board's `GET /api/board/media/<session>/<relpath>` byte route (a muted, metadata-only `<video>` for .mp4, an `<img>` for .gif/.png, captioned by the node name in the filename); the route streams whole files, so scrubbing a clip waits on its download.

- **Live in-flight state.** The cockpit shows the last *sealed* `task.plan_complete` tree, not interim stage progress. The operational feed (`runtime_events.jsonl`, read by `board.store.read_runtime_events`) already drives the rail's mission card between a live/running render and its settled (收场) final line; animating the cockpit graph's in-flight node from that same feed is still deferred.
- **Settled dwell is fixed.** After a run seals, the mission card's final line lingers `SETTLE_MS` (30s) before yielding to idle; a new run re-reveals it. Fixed constant, not config — expose it only if an operator asks.
- **Node evidence renders inline** in the cockpit rather than routing to the right-hand `details` slot. Cross-slot session-scoped selection wiring is deferred; the inline panel is self-contained.
- **Per-poll board calls.** The rail drives seven-plus board reads per 15s poll (sessions, session, session_progress, runtime_status, runtime_events, stores, then rsi_campaigns for the evolution session's newest campaign), each a cold `board.storecli` subprocess. Fine at human cadence on tiny stores; batch into one read fn if poll latency is ever measured to matter.
- **Cards are not individually collapsible.** The section scrolls as a whole; add per-card collapse if the rail grows.
