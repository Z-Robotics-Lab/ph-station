# @deepseek-ai/dsh-client-ui-ph-ops

[English](README.md) | 中文

physical-harness 指挥员侧栏 + 任务驾驶舱 + RSI 页。若干浏览器面，通过 board Remote 读取 harness 证据层并只做渲染：

- **任务驾驶舱** —— 一个 `conversation.view` 标签页（任务图）。运行中任务的 graph-first 视图：目标 → 任务节点 → 阶段流水线，加上 capability 接线扇形，一张可交互的 React Flow DAG（平移/缩放、minimap、点击选中）。运行历史条在已封存的任务尝试之间切换；点击节点在图旁打开其证据（阶段、故障、provider `ref`）。状态色沿用既定三色（绿过 / 红败 / 中性待定），与战报/演进/账本读作同一套系统。
- **技能库** —— 由 [`ui-ph-vault`](../ui-ph-vault/README.zh.md)（view id `vault`，技能库）拥有技能记录及其展示。本包不注册技能标签页。
- **RSI 页** —— `conversation.view` 标签页 `rsi` 启动或继续 evolve 简报、取消尚未结束的简报，并选择持久保存的 campaign 与轮次。页面保留实时阶段步进条、种子与节点进度、运行帧、训练曲线和分页轮次历史、逐种子基线/试探矩阵、视频片段、丢弃片段的关键帧、用量和运行日志。board 调用失败时明确报错，包括提交和取消的 RPC 错误。取消失败时保留待处理简报，允许重试。运行中每 2s 读取一次，否则每 10s；完整证据仅按选中的轮次读取。`evaluation` 展示固定任务目标、前后成功计数与进度、开发评测是否接受及其理由，以及独立的验证安装状态。试探改进不会把 `not_evaluated` 变成已安装。曲线使用后端的固定条件进度；历史节点通过率标为诊断数据。轮次表记录明确的开发评测接受；旧发布和确认记录明确标为历史记录。可展开的 `diagnosis` 与 `experience` 原样保留后端证据。`transfer` 展示先前任务数、首次接受轮次、尝试总数、预算内尚未观察到接受的情况、记录中的条件与经验检索截点，并原样展示后端对结论范围的说明。可选的 `confirm` 阶段标为额外开发种子复测；种子面板仅展示已报告的额外种子，不把它们视为留出集安装证据。存在旧 store 时，原有严格评测视图仍折叠保留在 campaign 下方。面板宽度超过 860px 时，媒体与分析采用等宽双列，否则纵向堆叠。实时帧高度上限为 440px，视频卡片为 260px，均以 `object-fit: contain` 保留完整画面。图表铺满分析列，日志保持全宽。
- **指挥员侧栏** —— 一个 `sidebar.section` 占位：常驻的扫视卡片栈（任务小地图、进度、运行时体征、RSI ticker——进化态会话经 `rsiCampaigns` 得到的最新 campaign（运行中的优先；重启后仍在）的 `任务 · 第 r 轮 · best k/n · 状态`，仅当存在旧式 store 时下面再加一行旧的晋升计数），不用点击就回答「任务到哪了 / 有没有在推进 / 机器健康吗 / 有没有变好」。侧栏收成图标条时折叠为状态点。

每个数字都来自 `board.store`——Python 的 `session_progress` 折叠与会话链——经 board Host Remote（`sessionProgress`、`session`、`sessions`、`runtimeStatus`、`runtimeEvents`、`hostVitals`、`modelServer`、`policyServer`、`restartServices`、`health`、`stores`、`cards`、`rsiCampaigns`、`rsiRun`、`rsiSeries`、`rsiFrames`）。这里不计算任何统计（宪章审定的硬规则：fork 渲染，Python 聚合）。体征卡还从 `hostVitals` 读主机本身的余量——每张 GPU 的显存及占用它的进程、内存、磁盘可用——走自己的 5s 轮询，因为这些量自己会动、没有 board 写入可跟随，而显存打满会直接打爆常驻 runtime；超过 90% 时进度条变红。阈值只决定颜色，绝不产生数字。在解释它的那条显存进度条下面，这张卡带着本面唯一的控制项：`modelServer` 启停本机的本地模型服务，徽章分停止 / 加载中 / 运行中（`running` 而非 `healthy` 就是那 1–2 分钟的加载），按钮在轮询确认切换完成之前一直保持按下。它只切换服务进程——请求发给哪个模型仍由模型选择器决定——侧栏传的是一个字面动作词；白名单、启动脚本路径与击杀护栏全在 `board.store` 那边。它旁边的 `policyServer` 是同一种开关，对象换成 pi0.5 策略服务（徽章分未启动 / 运行中（未就绪） / 服务中，附 checkpoint sha 短码），用显式的启动 / 停止两个按钮，并注明默认不启动、约占 18 GB 显存、不能与本地模型共存。最后，`restartServices` 重启 harness 服务，走控件内的两步确认（第一次点击进入待确认，8s 内再点一次才真正触发；绝不用 `window.confirm`），带一个“重建控制台后重启”复选框；触发后卡片显示重启中，并（先等一小段宽限，因为重启助手在控制台下线前就已答复）轮询 `health` 直到控制台恢复应答，再显示其 `restart` 行的状态与最后一行。侧栏读取 `runtimeEvents` 仅用于区分"运行中"与"已收场"——直接读 board 自己的 `task_claimed` / `task_done` / `task_failed` 标记，绝不在此计算判定。

RSI 训练曲线默认显示固定任务进度，可切换整任务成功率。曲线默认保留全部历史轮次，在目标或协议版本边界断线，并用虚线标出版本切换；也可单独选择一个版本，缺少标识的评估单独隔离。仅完成一轮时明确提示只有一个实测点。当前策略仅在后端明确接受后使用候选结果，否则使用该轮基线。候选以独立菱形显示，并用细线连接其配对基线。缺失观测与跳过的轮次会断开原始策略线，不平滑也不补值。可滚动的轮次表默认显示最近 20 轮，包含结果、策略与候选数值及投入。曲线与表格共用详情选择，方向键和 Home/End 可切换轮次。翻到旧页会固定所选轮次并退出实时跟随；“跟随最新”返回全部历史并持续显示新增结果。曲线测量容器宽度，窄屏轴文字保持可读。可展开的原始观测保留逐种子评估、验证器依赖（包括被阻断的读取）和终局观测。

新建与继续运行的 RSI 简报默认使用 `proposer: "llm", continuous: true, rounds: 0`；页面没有规则提议器选项，也没有自动回退。持续模式不断开始有预算上限的学习周期，直到用户取消或出现外部错误。有限模式提交 `continuous: false` 和正整数周期上限，并保留本次简报的共享预算。任务已有运行简报时禁止重复启动，等待下一周期时仍可停止。旧规则轮次明确标为历史，显式收件箱提案保留记录中的来源。LLM 审计区分 `proposed`（已提出候选）、`abstained`（模型主动放弃）、`rejected`（校验预算耗尽）和 `error`（模型调用失败），展示模型、提示摘要、理由及错误阶段、类型和消息。可展开的 JSON 保留 board 暴露的已封存审计摘要与哈希，不包含完整请求消息或模型原始答复。主动放弃和校验预算耗尽描述已结束的单周期，不代表持续运行已停止。状态区展示当前学习周期、距离下一周期的等待时间和整体停止原因，与所选轮次的周期结果及模型停止原因分开。模型调用错误以失败结束，并展开日志。`evaluation.after` 为 null 时标为未复测，曲线不产生复测进度点。

Campaign 读取绑定当前选择的会话和任务；完整证据与媒体还绑定所选轮次。切换任务时先显示加载状态，直到该任务的 campaign 返回；旧选择的迟到响应会被忽略，包括切走后再次选择同一任务的情况。不同任务即使轮次编号相同，也不会共用证据。若选中的轮次仍在运行，现有序列轮询首次报告其封存行时会重新读取该轮完整证据和媒体。

程序策略在线改进轮次在现有模型审计中展示模型调用、取证、探索试验次数、字节预算、输出 token 用量与记录的结束原因。请求字节按累计值统计；请求与工具结果上限分别按单次计算，输出 token 上限按单次模型调用计算。独立的 `run_budget` 记录本次提交简报内的累计消耗，不代表整个 campaign 历史，也不在周期之间清零。`cycle_budget` 展示当前周期的额度和消耗。持续运行简报中显式为 null 的总额度显示为无总上限，缺失测量仍为未知。当前状态与所选轮次审计保留各自的预算记录。缺失测量仍为未知，包括不完整的 API token 用量。这些计数描述模型环路，不包括控制台轮询。程序策略标识展示基线、候选、当前及父版本，并保留后端的更新决定；这是不训练权重的程序策略改进。可展开的学习记录保留探索 probe 与反馈，它们不构成配对开发评测接受或验证安装证据。固定任务结果与曲线仍展示权威的配对测量。

迁移资源成本按单个开发周期（epoch）统计。紧凑迁移视图显示记录的已接受改进次数、累计投入与首次接受改进投入，包括 episode 尝试、模型调用、输入字节、LLM tokens、仿真秒数和经过秒数。尚无首次接受时显示“尚未接受”；已有接受但成本未测量时逐项显示 `—`，已测量的零仍显示零。Token 是资源计数，不是金额估算。可展开的周期成本从所选轮次之前最近一次接受之后算起，包含所选轮次，即使该轮刚被接受。浏览器不累加这些记录，也不据此推导接受决定；缺少成本的历史轮次保留原有视图。

轮次图、任务热图与种子矩阵分别在自己的容器内横向滚动。较长的历史与标识符不会撑宽 RSI 面板或把媒体移出面板；面板较窄时，实时区域纵向排列。

记录包含 `llm.budget.limits.max_read_calls` 时，预算区显示每次新实测采样之间允许的批量只读调用上限。缓存结果与错误不会重置该额度。旧记录缺少此上限时不显示；控制台不根据取证总次数推算额度。

内部“运行 / 模型设置”页签将下次运行的草稿与战役已记录的 `llm_config` 分开展示。模型 ID 和推理强度选项来自 `rsiModelOptions`；列表查询失败时仍可直接输入模型 ID。留空会省略 `llm_model` / `llm_effort`，使用界面展示的后端默认值（`off` 关闭思考）。显式选择仅随下一次“开始 / 继续”简报提交。切换页签和刷新列表均保留草稿，不会重启正在运行的简报。旧战役缺少已记录配置时保持未知。选中轮次同时展示请求的模型、推理强度与实际模型标识。

## 依赖

两个净新增运行时依赖，均为 MIT，依重设计规范（`physical-harness/docs/ph-ui-redesign.md` §5）论证：

- **`@xyflow/react`**（React Flow v12）—— 可交互任务 DAG：自定义状态着色节点、平移/缩放、minimap、受控选中支撑点击下钻。用 SVG 手写是更大的 diff 且交互/可访问性更差。React Flow 渲染自己的 DOM 子树，不继承面板语言；`ops.module.css` 用 `currentColor`（随应用主题翻转）覆写其 `--xy-*` 变量并设置 `colorMode="system"`。
- **`@dagrejs/dagre`** —— 给 React Flow（不自动定位）供位的分层 DAG 布局。小巧，且对我们个位数到几十的节点数足够。

## 模型体验

无，因为两个面都只为浏览器操作员渲染 board Remote 状态；对话 LLM（大语言模型）通过 MCP 服务器读取同一批 `board.store` 函数。

#### KV Cache 影响

无；本包从不组装或发送 provider 请求。

## 已知限制与暂缓事项

- **片段流式播放但不支持 Range。** 关键片段 把每条 `rsiFrames` 路径渲染成一张卡片，字节来自 board 的 `GET /api/board/media/<session>/<relpath>` 路由（.mp4 用静音、仅预载元数据的 `<video>`，.gif/.png 用 `<img>`，说明文字是文件名里的节点名）；路由整文件流出，所以拖动进度条要等下载。

- **实时进行中状态。** 驾驶舱显示最后*封存*的 `task.plan_complete` 树，而非中途的阶段进度。实时 feed（`runtime_events.jsonl`，由 `board.store.read_runtime_events` 读取）已用于驱动侧栏任务小图在"运行中"渲染与"已收场"终局行之间切换；用同一 feed 给驾驶舱图里进行中的节点做动画仍被推迟。
- **收场停留时长固定。** 一次运行封存后，任务小图的终局行停留 `SETTLE_MS`（30 秒）再让位给空闲态；有新运行会重新显示。固定常量而非配置——除非操作员要求，否则不外露。
- **节点证据内联渲染**在驾驶舱里，而不是路由到右侧 `details` slot。跨 slot 的会话作用域选中接线被推迟；内联面板自成一体。
- **每次轮询的 board 调用。** 侧栏每 15s 轮询驱动七次以上 board 读取（sessions、session、session_progress、runtime_status、runtime_events、stores，再为进化态会话的最新 campaign 读 rsi_campaigns），每次都是一个冷的 `board.storecli` 子进程。在小型 store 上以人类节奏没问题；若实测轮询延迟成为问题，再合并成单个读取函数。
- **卡片不能单独折叠。** 区块整体滚动；侧栏长大后再加每卡折叠。
