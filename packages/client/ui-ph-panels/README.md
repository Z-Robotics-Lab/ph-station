# @deepseek-ai/dsh-client-ui-ph-panels

English | [中文](README.zh.md)

The 规划 (plan), 技能库 (skill library), 演化台 (RSI console), 演进 (RSI monitor), 机箱 (chassis), and 账本 (ledger) panels plus the frame-wide status bar. Each is one slot entry that reads the harness evidence and planning layers through the `board` Host Remote and renders only — no service, no business logic. Every number and every verdict comes from `board.store` / `board.cards` / `board.planning`; TS formats (×100 for pp with sign, mtime → duration) but computes nothing.

- **演化台 head: Run RSI + chain stepper** (top of the aggregate RSI tab) — a launcher that replaces the hand-written `{"kind":"rsi","task":...}` brief: a task dropdown flattened from the 机箱 cards' `task_bindings`, a session dropdown of `runtime.boot` sessions whose live `runtimeStatus` mode is `evolution` (each with its heartbeat age; past ~10 min a gray "runtime may be dead (stale)" badge shows — a displayed fact that never blocks the submit), and a submit button that sends the two strings through `/api/board/submitBrief` with zero client-side validation (the runtime is the only authority; the returned `submitted` filename is echoed). Below it, the seven-step chain stepper (allocate → calibrate → gate → prereg → dev → held-out → install) positions itself from the newest rsi `campaignProgress` heartbeat's `stage`, and renders its done/total bar, the three seed blocks, the first-death distribution as small bars, and the gate's c1..c6 criteria as red/green chips from the sealed `runtime.rsi_scheduled` session row (falling back to the heartbeat's own verdict fields while the chain runs); a NO-GO renders as the labeled honest result, never an error state.
- **规划** (`conversation.view` tab) — a natural-language task box and simulator selector over `/api/board/planSkillTask` (RoboCasa is the installed simulator and maps to `session-robocasa`). The validated reply becomes a responsive visual skill graph: the goal and composite skills flow left to right, each composite card expands its leaf skills top to bottom, taxonomy paths and readable argument chips stay attached to their owning node, and bound/unbound dots and chips expose execution readiness without showing wire JSON. The status verdict (`executable` / `planning_only` / `rejected` / `no_match`), routed vocabulary, compact catalogue size, terminal node, and every missing binding remain visible harness facts. Execute is enabled only when the harness returned `executable: true`; it posts the returned `composite_plan` record to `/api/board/submitSkillPlan`, shows the brief id and state the harness answers with (queued / running / stalled / done / failed / cancelled, polled through `/api/board/briefStatus` every 2 s while live), and offers `/api/board/cancelBrief`. A refused submit is shown as a refusal. Model text is rendered as React text nodes, never as HTML.
- **技能库** (`conversation.view` tab) — `/api/board/skillLibrary` projects `unified_skill_graph.json` into a searchable Overall Skill Tree by default: `RobotSkill` is the root, parent/child cards and connectors draw the complete IS_A taxonomy, distinct node treatments separate roots, categories, observed skills, and canonical skills, and binding dots expose readiness. A compact collapsible outline remains available as a layout toggle. Selecting a node in either layout shows HAS_STAGE / REALIZES stages, DECOMPOSES_TO composition, bounded annotation labels and dataset evidence, exact binding state, and same-canonical implementation candidates. A second catalogue lists installed runtime skills with their task, policy, and argument schema; candidates never count as direct bindings.
- **演进** (`conversation.view` tab) — `/api/board/stores` + `/api/board/store` for per-generation Δpp bars (dev/blind/held-out deltas, promotion events, McNemar fixed/broken), and `/api/board/rounds` for the progress.md feed. `/api/board/campaignProgress` drives the 进行中 cards on top: one per running script-path battery (`runs/*/progress.json` heartbeat) with its done/total bar, success count, first-death top-3 chips, and an ETA that is a pure display conversion of the python-provided timestamps; the heartbeat alone tightens to a 5s poll while a campaign runs, and the cards render nothing (no reserved space) when none does.
- **机箱** (`conversation.view` tab) — `/api/board/cards` card grid: name, actuation, needs_sim, contribute counts, and manifest summary. The doctor is not wired (no `scripts/plugin_doctor.py` yet), so a labeled `体检: 未接入` slot stands in — never faked.
- **账本** (`conversation.view` tab) — `/api/board/ledger` seed-block table: range, burn state, source line. `parse_ledger` returns no task / holdout field, so those columns are absent rather than invented.
- **status bar** (`shell.overlay` strip) — MODE + boot facts from the newest runtime session's `runtime.boot` row (`/api/board/sessions` + `/api/board/session`), a heartbeat from the session mtime, and board-bridge reachability from whether the fetch worked. When the boot row carries a `render` key it also shows a 取景窗 on/off chip; rows without the key (older sessions) show no chip — presence is the signal, never a guess.
- **任务台 chips** (`conversation.input.dock` row above the composer) — small preset buttons (stack / lift_geometric task, latest battle report) that prefill the composer draft with an editable prompt template via the session input face; they never submit — the operator edits seed/params and sends.

Live-data panels and the status bar re-fetch on a shared 15s poll, paused while the tab is hidden and re-run the moment it returns; a failed poll keeps the last good data. The skill library loads once and offers an explicit refresh because its sources change only when the generated graph or installed plugins change. When the board bridge is not mounted (a plain `dsh web` with no `PH_BOARD_*` env), each panel reports the data plane unavailable.

## Model Experience

None from this package's own requests: the panels render board Remote state and the 任务台 chips only prefill an editable composer draft, which reaches the model as an ordinary user message only when the operator sends it. The 规划 panel's Plan button makes the harness call its own planner model (DeepSeek through the motherboard's `plugins/planner_vlm`) with a compact skill catalogue; that request is assembled and bounded harness-side and never passes through this package or the chat session.

#### KV Cache effect

None; the package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- Fixed 15s polls rather than an mtime-driven refresh; adequate for the small `runs/` tree, revisit if it grows large.
- The 规划 panel previews a plan the resident runtime re-derives from the brief with the same planner and validator; the previewed chain is advisory and the runtime's sealed plan is the evidence.
- The 演进 Δpp bars use a fixed 40pp full-scale reference (a glance cue; the exact signed value sits beside every bar).
